# Subagents

A **subagent** is a focused, single-purpose AI worker invoked by the main agent for a specific job (code review, exploration, planning, etc.). It runs with its own system prompt, tool allowlist, and optionally its own model. Outputs flow back to the parent as a single tool result.

The most common AI failure mode is making subagents too generic — "an agent that helps with the codebase". A good subagent has a tight scope (one job, one or two paragraphs of system prompt) and an aggressive description that delegates well. If you can't write a one-sentence trigger for it, the responsibility isn't carved cleanly.

## Where subagents live

Source of truth in this repo:

```
~/.dotfiles/ai/agents/<name>.md     # single-file format
```

| Tool | Path | Format |
|---|---|---|
| Grok (canonical) | `~/.grok/agents/<name>.md` | Markdown + YAML frontmatter (direct symlink) |
| OpenCode (adapter) | `~/.config/opencode/opencode.json` `agent.<name>` | JSON, generated by `generate-opencode-config.sh` from the markdown |

OpenCode also supports markdown agents natively at `~/.config/opencode/agents/` or `.opencode/agents/`. This repo uses the JSON-merge adapter so a single markdown file feeds Grok and OpenCode. Don't author a second OpenCode-only markdown copy.

## Frontmatter — Grok first, OpenCode adapter keys optional

```yaml
---
name: code-reviewer          # required; lowercase + hyphens; match the filename
description: ...             # required; drives delegation (see below)
model: grok-build            # Grok model id; omit to inherit the parent
tools: Read, Grep, Glob      # Grok allowlist (comma- or space-separated)
mcpInheritance:              # Grok: what parent MCP servers the child sees
  all: true                  # or `none`, or `named: […]` / `except: […]`

# OpenCode adapter (ignored by Grok):
mode: subagent               # primary|subagent|all (default: all)
permission:                  # preferred OpenCode form (replaces tools:)
  edit: ask                  # ask|allow|deny
  bash: { "*": ask, "git status": allow }
  webfetch: allow
temperature: 0.2             # 0.0-1.0
top_p: 0.9
steps: 30                    # max agentic iterations
hidden: false                # hide from OpenCode @ autocomplete
color: blue                  # or hex
---
```

**Body**: the markdown after the frontmatter is the agent's system prompt. Keep it scoped — role, focus, what to avoid. A few hundred words is usually plenty.

Grok also documents spawn-time `isolation` (`none` | `worktree`) and `capability_mode` (`read-only` | `read-write` | `execute` | `all`) on `spawn_subagent` — those are invocation params, not something you have to put in every file. Plugin-shipped agents cannot declare their own `mcpServers` or hooks, and cannot set `permissionMode: bypassPermissions`. User-authored agents in this repo are not plugins.

Don't author Claude-only fields (`permissionMode`, `memory`, `initialPrompt`, `disallowedTools`) expecting this installer to do something with them.

## The description is the delegation cue

When the parent decides whether to call a subagent (`spawn_subagent` / OpenCode `task`), it reads the description. Same rules as skills:

1. State the job in one sentence.
2. Add "Use proactively when…" or "Use when the user asks…" with concrete triggers.
3. Include the file types or domains it covers.

```yaml
description: Reviews diffs for security and style issues. Use proactively after code changes to flag bugs, secrets, OWASP risks, or violations of project conventions.
```

## Model selection

| Value | Effect |
|---|---|
| `grok-build` | Cheap/fast — default for new subagents in this repo (matches `[subagents] default_model`) |
| other Grok model id | Passed through to Grok as-is |
| `provider/model-id` | Full OpenCode provider id; generate script keeps it if it contains `/` |
| omitted | Grok inherits the parent; OpenCode uses its configured default |

Do **not** use `sonnet` / `opus` / `haiku`. The generate script no longer maps those to Anthropic.

## Tools

### Grok (`tools:`)

Comma- or space-separated list of tool names. Omit to inherit everything.

```yaml
tools: Read, Grep, Glob, Bash, Edit
```

Claude-shaped names work because Grok aliases them (`Read` → `read_file`, `Bash` → `run_terminal_command`, `Grep` → `grep`, `Edit`/`Write` → `search_replace`, `Task` → `spawn_subagent`). Prefer the names already used in this repo's agents (`Read`, `Grep`, `Glob`, `Bash`) unless you're matching a Grok-native tool (`search_tool`, `use_tool`, `spawn_subagent`).

MCP inheritance is separate — see `mcpInheritance` above. Default is inherit all parent-connected servers.

### OpenCode adapter (`permission:` preferred)

The generate script currently emits the **deprecated** `tools: { read: true }` boolean form from the markdown `tools:` list. That's a known gap. If an OpenCode session needs real gating, add a `permission:` block to the markdown; you may also need to extend `generate-opencode-config.sh` to emit it (it does not today).

```yaml
permission:
  edit: deny
  bash:
    "*": ask
    "git status": allow
    "git diff *": allow
  read: allow
  webfetch: deny
```

Keys: `read`, `edit`, `glob`, `grep`, `list`, `bash`, `task`, `external_directory`, `todowrite`, `webfetch`, `websearch`, `lsp`, `skill`, `question`, `doom_loop`.

## Portability — system prompts must be tool-agnostic

The markdown body becomes the system prompt in Grok and (via generate) in OpenCode. Write it for "the agent":

| Do this | Not this |
|---|---|
| "Read files with the Read tool" | "Use Grok's Read tool" |
| "Run shell commands via Bash" | "Use the `bash` tool in OpenCode" |
| "If you need to delegate, spawn a subagent" | "Use the `spawn_subagent` tool" |

Grok-shaped `tools:` and OpenCode `permission:` / `mode:` can coexist. Each runtime ignores keys it doesn't understand. If the agent legitimately needs to behave differently in OpenCode, that's a sign it should be two agents, not one with conditionals in the prompt.

## Body — the system prompt

- **Define the role in one sentence.** "You are a senior code reviewer focused on security."
- **State the scope.** What does it touch? What's out of scope?
- **Give a workflow.** Three to five numbered steps.
- **Define the output shape.** Markdown report? JSON? Pass/fail verdict?

```markdown
You are a senior security reviewer. Your job is to read code changes and flag bugs,
secrets, and OWASP top-10 risks before they ship.

Workflow:
1. Run `git diff origin/main..HEAD` to see the change.
2. For each modified file, read it in full (not just the diff).
3. Flag: secret leakage, SQLi, XSS, deserialization, missing auth, command injection.
4. Output a markdown report with severity (HIGH/MED/LOW) and file:line refs.

Out of scope: style, formatting, test coverage — that's other reviewers' jobs.
```

## Invocation paths

| Tool | How parents invoke |
|---|---|
| Grok | `spawn_subagent` with `subagent_type: <name>`; `/config-agents` (alias `/agents`) to manage |
| OpenCode | `@<name>` in chat, or the `task` tool. Primary agents (`mode: primary` or `all`) cycle via Tab |

## OpenCode `mode` field

| Mode | Behavior |
|---|---|
| `primary` | User-facing top-level agent (Tab cycles) |
| `subagent` | Only invoked by other agents via `@name` or `task` |
| `all` (default) | Both |

For helpers (code-reviewer, scout, planner), set `mode: subagent`.

## Minimal canonical example

See [`examples/agent.template.md`](examples/agent.template.md). Compact form:

```markdown
---
name: code-reviewer
description: Reviews diffs for security and style. Use proactively after code changes.
model: grok-build
tools: Read, Grep, Glob, Bash
mode: subagent
permission:
  edit: deny
  bash: { "*": ask }
---

You are a senior code reviewer. Read the diff, focus on correctness and security,
output a short markdown report with file:line refs.
```

## Editing an existing agent

1. Save `~/.dotfiles/ai/agents/<name>.md`.
2. `dot update` — re-links Grok and regenerates OpenCode agent JSON. Or `dot install grok` / `dot install opencode` for one side.
3. Verify with `grok inspect`.

The JSON regeneration is non-destructive: `generate-opencode-config.sh` only touches managed keys (`.agent`, `.command`, `.instructions`, `.plugin`) and strips `.provider.anthropic`. Personal `opencode.json` is preserved.

## Common mistakes

- **Defaulting `model` to `sonnet`.** Use `grok-build` (or omit).
- **`name` field that doesn't match the filename.** Keep them in sync.
- **Model: `*` or `any`.** Not supported. Omit to inherit.
- **Inline MCP server definitions in agent frontmatter.** Configure MCP centrally via `ai/mcp-servers.json.tpl`. Use `mcpInheritance` to filter what the child sees.
- **Long system prompts.** A 2,000-word system prompt usually means the agent is doing too much. Split or move depth into a referenced skill.
- **Expecting OpenCode `permission:` to be generated today.** The adapter still emits deprecated boolean `tools`. Track that if you need real OpenCode gating.
