# Subagents

A **subagent** is a focused, single-purpose AI worker invoked by the main agent for a specific job (code review, exploration, planning, etc.). It runs with its own system prompt, tool allowlist, and optionally its own model. Outputs flow back to the parent as a single tool result.

The most common AI failure mode is making subagents too generic — "an agent that helps with the codebase". A good subagent has a tight scope (one job, one or two paragraphs of system prompt) and an aggressive description that delegates well. If you can't write a one-sentence trigger for it, the responsibility isn't carved cleanly.

## Where subagents live

Source of truth in this repo:

```
~/.dotfiles/ai/agents/<name>.md     # single-file format
```

| Harness | Path | Format |
|---|---|---|
| Grok | `~/.grok/agents/<name>.md` | Markdown + YAML frontmatter (symlink; rendered file when it sets `job:`) |
| OpenCode | `~/.config/opencode/opencode.json` `agent.<name>` | JSON, generated by `generate-opencode-config.sh` from the markdown |
| Claude Code | `~/.claude/agents/<name>.md` | Markdown + YAML frontmatter (symlink; rendered file when it sets `job:`) |

OpenCode also supports markdown agents natively at `~/.config/opencode/agents/` or `.opencode/agents/`. This repo generates JSON instead so a single markdown file feeds all three. Don't author a second harness-only copy.

## Frontmatter — shared keys plus harness-specific ones

```yaml
---
name: code-reviewer          # required; lowercase + hyphens; match the filename
description: ...             # required; drives delegation (see below)
job: review                  # model + effort per harness from ai/models.yaml
tools: Read, Grep, Glob      # Grok + Claude allowlist (comma- or space-separated)
mcpInheritance:              # Grok: what parent MCP servers the child sees
  all: true                  # or `none`, or `named: […]` / `except: […]`

# OpenCode (ignored by Grok and Claude):
mode: subagent               # primary|subagent|all (default: all)
permission:                  # preferred OpenCode form (replaces tools:)
  edit: ask                  # ask|allow|deny
  bash: { "*": ask, "git status": allow }
  webfetch: allow
temperature: 0.2             # 0.0-1.0
top_p: 0.9
steps: 30                    # max agentic iterations
hidden: false                # hide from OpenCode @ autocomplete
color: blue                  # or hex
---
```

**Body**: the markdown after the frontmatter is the agent's system prompt. Keep it scoped — role, focus, what to avoid. A few hundred words is usually plenty.

Grok also documents spawn-time `isolation` (`none` | `worktree`) and `capability_mode` (`read-only` | `read-write` | `execute` | `all`) on `spawn_subagent` — those are invocation params, not something you have to put in every file. Plugin-shipped agents cannot declare their own `mcpServers` or hooks, and cannot set `permissionMode: bypassPermissions`. User-authored agents in this repo are not plugins.

## Claude Code fields

Claude Code reads more frontmatter than the shared keys, and these are worth reaching for when a new agent has a context, cost, or safety need. They never reach OpenCode: the generator reads only `name`, `description`, `model`, `job`, `tools`, and `disallowedTools`. Grok ignores keys it doesn't know but shares a few names (`permissionMode`, `mcpServers`, `hooks`); if you set one of those, check what Grok does with it via `grok inspect`. The list grows between releases, so re-check [the supported fields table](https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields) before relying on a field you haven't used.

| Field | Values | Reach for it when |
|---|---|---|
| `disallowedTools` | same format as `tools` | Inherit everything except a few tools. `Bash(git push *)` still removes all of Bash |
| `permissionMode` | `default`, `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`, `plan` | The agent should run under a different permission mode than the parent |
| `maxTurns` | integer | Cap a runaway loop; output comes back marked partial and can be resumed |
| `autoCompactWindow` | tokens, `100000`–`1000000` | A log- or dump-heavy agent should compact earlier. Only lowers the window; `CLAUDE_CODE_AUTO_COMPACT_WINDOW` overrides it, and `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` applies to subagents too |
| `skills` | list of skill names | Preload full skill bodies at startup instead of hoping the agent invokes them |
| `mcpServers` | server names or inline configs | Narrow the agent's MCP servers. In this repo, name roster servers only; no inline definitions |
| `hooks` | hook config | Lifecycle hooks that run only while this agent is active |
| `memory` | `user`, `project`, `local` | The agent should keep notes across sessions |
| `background` | `true` | Keep it in the background even when the parent asks to wait |
| `omitClaudeMd` | `true` | The delegation prompt carries everything; skip CLAUDE.md to save context |
| `effort` | `low`, `medium`, `high`, `xhigh`, `max` | Set it through `job:` instead; the rendered file carries the job's effort. `CLAUDE_CODE_EFFORT_LEVEL` still wins |
| `isolation` | `worktree` | The agent edits files and must not touch the parent's checkout. Branches from the default branch, not the parent's HEAD |
| `color` | `red`, `blue`, `green`, `yellow`, `purple`, `orange`, `pink`, `cyan` | Display only. Named colors only; OpenCode's hex form is invalid here |
| `initialPrompt` | string | Used only when the agent runs as the main session (`claude --agent`) |
| `experimental.cacheTtl` | `5m`, `1h` | Pick the prompt-cache lifetime for the agent's requests |

## The description is the delegation cue

When the parent decides whether to call a subagent (`spawn_subagent` / OpenCode `task` / Claude `Agent`), it reads the description. Same rules as skills:

1. State the job in one sentence.
2. Add "Use proactively when…" or "Use when the user asks…" with concrete triggers.
3. Include the file types or domains it covers.

```yaml
description: Reviews diffs for security and style issues. Use proactively after code changes to flag bugs, secrets, OWASP risks, or violations of project conventions.
```

## Model selection

Pin a model with `job: <name>`. `ai/models.yaml` gives each job a model and effort per harness (a profile's `models:` block overrides them on one machine). The Claude and Grok installers render a job agent into a real file with `model` and `effort` filled in, replacing it on every `dot update`; the OpenCode generator sets `model` and `variant`. Body edits to a job agent take effect on the next `dot update`, not live.

Without a job:

| Value | Effect |
|---|---|
| omitted | Grok and Claude inherit the parent; OpenCode uses its configured default |
| `grok-build` | Cheap/fast Grok model (matches `[subagents] default_model`); dropped by the OpenCode generator |
| other Grok model id | Passed through to Grok as-is |
| `provider/model-id` | Full OpenCode provider id; generate script keeps it if it contains `/` |

A model id names one harness's models. `sonnet` / `opus` / `haiku` mean something only to Claude, `grok-*` only to Grok; the OpenCode generator drops any id without a `/`.

## Tools

### Grok and Claude (`tools:`)

Comma- or space-separated list of tool names. Omit to inherit everything.

```yaml
tools: Read, Grep, Glob, Bash, Edit
```

Claude's names work in Grok because Grok aliases them (`Read` → `read_file`, `Bash` → `run_terminal_command`, `Grep` → `grep`, `Edit`/`Write` → `search_replace`, `Task` → `spawn_subagent`). Prefer the names already used in this repo's agents (`Read`, `Grep`, `Glob`, `Bash`) unless you're matching a Grok-native tool (`search_tool`, `use_tool`, `spawn_subagent`).

MCP inheritance is separate — see `mcpInheritance` above. Default is inherit all parent-connected servers.

### OpenCode (`permission:` preferred)

The generate script emits the **deprecated** `tools: { read: true }` boolean form from the markdown `tools:` list, which does not gate anything. For a read-only agent, set `disallowedTools: Write, Edit`: Claude and Grok drop those tools, and the generator emits `permission: { edit: deny }` for OpenCode. Other `permission:` keys are not generated.

```yaml
permission:
  edit: deny
  bash:
    "*": ask
    "git status": allow
    "git diff *": allow
  read: allow
  webfetch: deny
```

Keys: `read`, `edit`, `glob`, `grep`, `list`, `bash`, `task`, `external_directory`, `todowrite`, `webfetch`, `websearch`, `lsp`, `skill`, `question`, `doom_loop`.

## Portability — system prompts must be tool-agnostic

The markdown body becomes the system prompt in all three harnesses (OpenCode via the generator). Write it for "the agent":

| Do this | Not this |
|---|---|
| "Read files with the Read tool" | "Use Grok's Read tool" |
| "Run shell commands via Bash" | "Use the `bash` tool in OpenCode" |
| "If you need to delegate, spawn a subagent" | "Use the `spawn_subagent` tool" |

`tools:` and OpenCode `permission:` / `mode:` can coexist. Each harness ignores keys it doesn't understand. If the agent legitimately needs to behave differently in one harness, that's a sign it should be two agents, not one with conditionals in the prompt.

## Body — the system prompt

- **Define the role in one sentence.** "You are a senior code reviewer focused on security."
- **State the scope.** What does it touch? What's out of scope?
- **Give a workflow.** Three to five numbered steps.
- **Define the output shape.** Markdown report? JSON? Pass/fail verdict?

```markdown
You are a senior security reviewer. Your job is to read code changes and flag bugs,
secrets, and OWASP top-10 risks before they ship.

Workflow:
1. Run `git diff origin/main..HEAD` to see the change.
2. For each modified file, read it in full (not just the diff).
3. Flag: secret leakage, SQLi, XSS, deserialization, missing auth, command injection.
4. Output a markdown report with severity (HIGH/MED/LOW) and file:line refs.

Out of scope: style, formatting, test coverage — that's other reviewers' jobs.
```

## Invocation paths

| Tool | How parents invoke |
|---|---|
| Grok | `spawn_subagent` with `subagent_type: <name>`; `/config-agents` (alias `/agents`) to manage |
| OpenCode | `@<name>` in chat, or the `task` tool. Primary agents (`mode: primary` or `all`) cycle via Tab |
| Claude Code | The `Agent` tool with `subagent_type: <name>`; `/agents` to manage |

## OpenCode `mode` field

| Mode | Behavior |
|---|---|
| `primary` | User-facing top-level agent (Tab cycles) |
| `subagent` | Only invoked by other agents via `@name` or `task` |
| `all` (default) | Both |

For helpers (code-reviewer, scout, planner), set `mode: subagent`.

## Minimal example

See [`examples/agent.template.md`](examples/agent.template.md). Compact form:

```markdown
---
name: code-reviewer
description: Reviews diffs for security and style. Use proactively after code changes.
tools: Read, Grep, Glob, Bash
mode: subagent
permission:
  edit: deny
  bash: { "*": ask }
---

You are a senior code reviewer. Read the diff, focus on correctness and security,
output a short markdown report with file:line refs.
```

## Editing an existing agent

1. Save `~/.dotfiles/ai/agents/<name>.md`.
2. Body edits are live in Grok and Claude for symlinked agents; a `job:` agent and OpenCode pick them up on `dot update`, which also links new agents everywhere.
3. Verify with `grok inspect` / Claude `/agents`.

The JSON regeneration is non-destructive for personal keys (`mcp`, etc.). `generate-opencode-config.sh` rewrites `.agent`, `.command`, `.instructions`, `.plugin`, and `.provider` from `ai/agents` + `opencode.json.tpl`. Personal Bedrock account IDs stay as `{env:BEDROCK_AWS_ACCOUNT_ID}`; work GovCloud uses `WORK_BEDROCK_API_KEY` (or `/connect` `amazon-bedrock-gov`), not the personal `/connect` token.

## Common mistakes

- **Pinning `model` on a shared agent.** Any id is one harness's model; set `job:` instead, or omit both to inherit.
- **`name` field that doesn't match the filename.** Keep them in sync.
- **Model: `*` or `any`.** Not supported. Omit to inherit.
- **Inline MCP server definitions in agent frontmatter.** Configure MCP centrally via `ai/mcp-servers.json.tpl`. Use `mcpInheritance` to filter what the child sees.
- **Long system prompts.** A 2,000-word system prompt usually means the agent is doing too much. Split or move depth into a referenced skill.
- **Expecting OpenCode `permission:` to be generated.** Only `edit: deny`, from `disallowedTools` naming Write or Edit.
